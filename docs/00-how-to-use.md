# 怎麼用這套文件讓 AI 開發

這份是給你（專案擁有者）看的。其他文件是給 AI 看的規格。

## 做法

1. 用 Claude Code 或 Codex 開啟 `shipment_QR` 資料夾。它們會自動讀 `CLAUDE.md` / `AGENTS.md`。
2. 一次只交代一個任務，用任務編號，例如「做 P1-01」。任務清單在 `06-phases.md`。
3. AI 回報完成後，照它說的方式自己看一次結果，沒問題再做下一個。
4. 想改需求時，直接跟 AI 說，並要它同步更新 `docs/` 裡的規格。規格和程式要保持一致，下一次開工的 AI 才不會照舊規格做。

## 起手指令（可以直接貼）

開始一個階段：

```
讀 AGENTS.md 和 docs/06-phases.md，告訴我第一階段有哪些任務、你打算怎麼做 P1-01。先不要動手，等我說好。
```

做一個任務：

```
做 P1-02。做完後跑測試，告訴我結果，以及我要怎麼自己確認。
```

請另一個 AI 檢查（Claude 寫的給 Codex 看，或反過來）：

```
檢查最近一次修改是否符合 docs/ 裡的規格和 AGENTS.md 的「不可違反的規則」。只列出有問題的地方，不要改程式。
```

改需求：

```
我想改一個需求：＿＿＿。先告訴我這會影響哪些文件和已完成的任務，等我同意後再改規格和程式。
```

一個階段做完：

```
第一階段的任務都做完了。照 docs/06-phases.md 的階段驗收清單逐項檢查，告訴我每一項通過或沒通過。
```

## 幾個提醒

- AI 說「完成」不等於真的能用。每個階段結束時，自己實際操作一次驗收清單。
- 第一階段有一項一定要你本人做：拿幾支手機實際掃標籤，確認報修網址點得開（`06-phases.md` 的 P1-09）。這件事 AI 做不了。
- 對外網址、SMTP 寄信帳號是要你提供的設定，AI 不會有。
