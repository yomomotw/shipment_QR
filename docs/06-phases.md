# 06 分階段任務

每個階段做完都能單獨上線使用。任務依編號順序做，做完打勾。每個任務的「驗收」是完成的定義，要實際驗證。

## 第一階段：台帳與 QR

目標：標籤產生器接上後端。產生標籤時設備資料存進台帳，QR 內含離線資料，設定對外網址後多帶報修網址。

- [x] **P1-01 專案骨架**
  建立 `02-architecture.md` 的目錄結構、FastAPI 進入點、SQLite 連線、Alembic、`/healthz`、Dockerfile 與 docker-compose。把 `vendor/qrcode.js` 複製到 `app/static/vendor/`。
  驗收：本機與 Docker 都能啟動，`/healthz` 回 200；`pytest` 可執行。把啟動與測試指令寫進 `AGENTS.md` 的「常用指令」。

- [x] **P1-02 使用者與登入**
  `user` 表、登入登出、三種角色的權限檢查、首次啟動用環境變數建立負責人帳號、使用者管理頁（FR-62）。
  驗收：未登入進後台會導向登入頁；客服進不了 `/admin/*`；停用的帳號無法登入。

- [x] **P1-03 系統設定**
  `settings` 表與設定頁（FR-60、FR-61），本階段先做對外網址、叫修電話、預設保固月數。
  驗收：叫修電話未設定時，建檔頁提示先去設定；修改已有值的對外網址會出現警告並需確認。

- [x] **P1-04 序號解析與保固計算**
  `services/serials.py`、`services/warranty.py`。規則見 FR-02、FR-04。
  驗收：`07-testing.md` 的序號與保固測試案例全部通過。

- [x] **P1-05 QR 文字組裝**
  `services/qr_payload.py` 與 `scan_code` 產生。規格見 `04-qr-label-spec.md`。
  驗收：`07-testing.md` 的 QR 文字測試案例全部通過，輸出與規格範例逐字相同。

- [x] **P1-06 設備建檔**
  `device`、`batch` 表、建檔表單（規格多行貼入、勾選 QR 欄位）、預覽、整批建立（FR-01 ~ FR-08、FR-10）。
  驗收：建立 50 台連號設備成功；序號與台帳重複時整批不建立並指出是哪幾個；QR 過密有提醒、超過容量會擋下。

- [x] **P1-07 標籤列印頁**
  把現有 `index.html` 的標籤版面與 QR 繪製拆到 `label.js` 與模板。批次列印頁、單台補印、ZIP 與 CSV 下載（FR-09、FR-12）。
  驗收：標籤上只有序號、型號、叫修電話三列；用 Playwright 截圖後解碼 QR，內容與 `device.qr_payload` 逐字相同；補印與首次列印的 QR 相同；A4 拼版與標籤機兩種版面輸出的 PDF 頁面尺寸正確。

- [x] **P1-08 台帳與公開設備頁**
  台帳列表與搜尋、設備詳情、修改設備、重新產生 QR（FR-11）。公開頁 `/d/{scan_code}`，本階段只顯示資料與撥號按鈕（FR-20、FR-21）。
  驗收：公開頁原始碼中找不到未勾選的欄位與客戶名稱；錯誤的代碼回 404；修改型號後設備頁提示 QR 是舊資料。

- [ ] **P1-09 實機掃描測試（使用者執行）**
  由使用者印出含報修網址的標籤，用多支手機與掃碼 App 測試，項目見 `04-qr-label-spec.md`。agent 負責準備測試用標籤與記錄表，並把結果寫進 `08-decisions.md`。
  驗收：記錄表填完；密度門檻依結果校正；若網址點不開，已回報使用者並等待決定。

**階段驗收：** 從建檔到印出標籤全程可操作；手機離線掃描可讀到型號、序號、叫修電話；設定對外網址後新標籤的 QR 最後一行是報修網址，點開能看到設備頁。

## 第二階段：線上報修與工單

目標：叫修流程能完整跑一輪（報修 → 受理 → 處理 → 完修 → 結案）。

- [ ] **P2-01 工單資料與狀態機**
  `ticket`、`ticket_event`、`attachment` 表，`services/tickets.py`。
  驗收：`03-data-model.md` 轉換表中每一條允許的轉換可執行，表外的轉換全部被拒；每次轉換產生一筆事件。

- [ ] **P2-02 客戶報修**
  公開頁加上報修表單、檔案上傳、頻率限制、重複報修處理、進度查詢頁（FR-22 ~ FR-25）。
  驗收：手機上可完成報修並拿到工單編號；同一設備有未結案工單時看到進度而不是表單；超過頻率上限被擋；上傳不允許的檔案類型被拒。

- [ ] **P2-03 後台工單**
  工單列表與篩選、詳情頁、手動建單、備註與附件、狀態操作（FR-30 ~ FR-34）。
  驗收：客服可用序號建立電話工單；`in_warranty` 在建單後修改設備保固日期也不變。

- [ ] **P2-04 Email 通知**
  SMTP 設定與測試信、`services/mailer.py`、`notification_log`、新工單通知負責人、客戶報修確認信（FR-40、FR-44、FR-23）。
  驗收：SMTP 設定錯誤時，報修仍然成功，後台看得到失敗紀錄；設定正確時收得到信。

**階段驗收：** 掃碼報修與電話建單都能產生工單，負責人收到通知信，工單可一路走到結案，設備詳情頁看得到這張工單。

## 第三階段：派工與現場作業

- [ ] **P3-01 指派與約定時間**（FR-36、FR-41）
  驗收：工程師只看得到指派給自己的工單，並收到指派通知信。

- [ ] **P3-02 過保報價**（FR-35）
  驗收：過保工單受理後進入待報價；客戶在進度頁同意前無法開始處理；拒絕後可取消工單。

- [ ] **P3-03 工程師掃碼**（FR-37）
  驗收：已登入的工程師開啟報修網址會進到後台設備頁，看得到工單與歷史紀錄；未登入時看到的是客戶頁。

- [ ] **P3-04 完修紀錄與簽名**（FR-38）
  驗收：未填故障原因與處理方式無法完修；手機上可手寫簽名並存檔。

- [ ] **P3-05 客戶進度通知與未受理提醒**（FR-42、FR-43）
  驗收：受理、約定時間、完修各寄一封信給客戶；工單超過設定時數未受理會再通知負責人一次，且不重複寄。

**階段驗收：** 一張過保工單可走完報價、指派、到場、完修簽名、結案的完整流程。

## 第四階段：報表與延伸功能

- [ ] **P4-01 報表**（FR-50 ~ FR-53）
  驗收：用測試資料核對四張報表的數字與手算結果一致。

- [ ] **P4-02 常見問題**（FR-26）
  驗收：公開設備頁顯示該型號的常見問題；沒有資料的型號不顯示這個區塊。

**階段驗收：** 負責人可在報表頁看到四張報表並下載 CSV。
